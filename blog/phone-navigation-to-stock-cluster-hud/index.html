폰 길안내를 순정 계기판 HUD 규칙에 맞추기

2026.11.264분 분량

  • Android
  • Embedded
  • Automotive
  • Java
  • Testing

공개 저장소 Chunwol/gen5w-kr는 2020년식 차량의 표준형 내비게이션(Android 4.4 기반 헤드유닛)에서 휴대폰 길안내를 계기판과 HUD에 보이게 하는 개인 프로젝트입니다. 이번에는 “순정 내비만큼만 정확하게”를 기준으로 회전 표시 규칙을 다시 맞췄습니다. 아래 내용은 로컬 테스트와 독립 코드 감사까지 확인한 것이고, 실제 차량에서는 아직 확인하지 않았습니다. 이번 변경은 실차 확인 전이라 아직 공개 저장소에 올리지 않았습니다.

기준을 순정 동작에 두기

계기판은 회전 종류를 1바이트 아이콘 코드로 받습니다. 처음에는 길안내 앱이 주는 회전 종류를 그럴듯한 아이콘에 직접 연결했는데, 몇 가지가 순정과 달랐습니다.

  • 좌·우 분기(fork)가 목적지 깃발 아이콘으로 나가고 있었습니다.
  • 합류, 회전교차로, 페리는 아무 아이콘도 나가지 않았습니다.
  • 일부 코드는 계기판에 화살표 대신 로딩 스피너를 그렸습니다.

헤드유닛에 이미 있는 순정 Android Auto 수신부가 같은 입력을 어떻게 바꾸는지를 기준표로 삼아 다시 맞췄습니다. 분기는 순정 분기 아이콘, 합류는 직진, 페리는 페리 아이콘으로 바꿨습니다. 스피너를 그리는 코드는 어느 경로로 들어오든 직진으로 바꿔서 보내지 않게 했습니다.

국내 길안내 앱은 고가도로·지하차도·터널 진입을 “분기”로 보내는 경우가 많습니다. 그래서 분기에 붙어 온 도로명과 안내 문구가 고가·지하를 분명히 가리킬 때만 순정 고가·지하 아이콘을 쓰고, 그렇지 않으면 일반 분기 아이콘을 씁니다.

회전교차로 각도

AndroidX Maneuver의 회전교차로 각도는 “나가는 방향”이 아니라 “회전교차로 안에서 돈 각도”입니다. 반시계 방향 회전교차로라면 180°가 직진, 90°가 우회전, 270°가 좌회전, 360°가 U턴입니다. 이 각도를 45° 단위로 나눠 순정 출구 아이콘 8개 중 하나로 대응시켰습니다. 시계 방향 회전교차로는 같은 방향에 다른 아이콘 묶음을 씁니다. 출구 정보 없이 “회전교차로 진입/나가기”만 오는 단계에서는 직전 출구 아이콘을 유지해, 회전 중에 화살표가 직진으로 바뀌는 일을 막았습니다.

테스트에서는 모든 회전 종류와 각도 조합을 돌려 스피너 코드가 하나도 나오지 않는지 확인합니다.

거리 표시

  • 3km보다 먼 회전은 순정처럼 직진으로 표시합니다.
  • 300m 안에서는 접근 막대를 보내되, 순정처럼 빈 막대가 되지 않도록 최소 1칸을 유지합니다.
  • 별도 거리 필드는 큰 값이 들어와도 넘치지 않게 65534.9km에서 멈추게 했습니다. 처음 구현은 반올림용 값을 더한 뒤에 상한을 걸어서 아주 큰 입력에서 넘쳤습니다.

전달 확인이 안 되는 API에서 터널 신호 다루기

차량에는 “앞에 터널이 있다”는 보조 신호가 있어, 공조 내기 순환 같은 동작에 쓰일 수 있습니다. 이 신호를 다루면서 세 가지 성질이 문제가 됐습니다.

  1. 패킷 전체를 덮어씁니다. 이 신호는 주차장·공조 경고 필드와 한 패킷으로 묶여 있고, 읽어 오는 함수가 없습니다. 그래서 터널 필드만 채우고 나머지는 순정 4인자 함수와 같이 0으로 둡니다. 근거 없는 공조 값을 만들어 넣지 않습니다.
  2. 다른 송신자도 같은 패킷을 씁니다. 순정 내비가 그 사이 패킷을 바꿀 수 있으므로, 활성 터널은 3초마다 다시 보냅니다.
  3. 실패를 알려 주지 않습니다. 차량의 클러스터 API는 프로세스 간 호출 오류를 내부에서 조용히 삼킵니다. 함수가 정상 반환해도 전달됐다는 보장이 없습니다. 해제 신호가 한 번 유실되면 터널 신호가 계속 켜진 채 남을 수 있으므로, 해제는 1초 간격으로 2번 더 보내고 멈춥니다.

소유 관계도 한 곳에서 정리했습니다. CarPlay와 Android Auto의 터널 요청을 하나의 함수가 합치고, CarPlay 안내가 시작되면 Android Auto가 걸어 둔 터널은 바로 해제합니다. 순정 안내가 시작되거나 누가 안내 중인지 알 수 없으면 Android Auto 터널 요청을 버립니다. 순정 안내 중에는 폰 쪽에서 이 신호를 아예 쓰지 않습니다. GPS가 끊겨 거리를 모를 때는, 이미 1km 안에서 켜진 터널만 유지하고 멀리 있는 터널을 새로 켜지 않습니다.

검증과 남은 것

  • JVM 단위 테스트와 Python 기반 수명주기 테스트에 회귀 사례를 추가했습니다. 터널 재전송, 해제 반복 횟수 제한, CarPlay 전환, 순정 소유 전환, GPS 끊김, 회전교차로 각도, 거리 포화가 포함됩니다.
  • 별도 AI 코드 감사로 1차 검토했고, 지적된 두 건(순정 전환 뒤 남는 터널 요청, 실패한 해제를 성공으로 기록하는 문제)을 고쳤습니다. 2차 자동 감사는 사용량 한도로 끝나지 못해, 같은 범위를 직접 다시 검토했습니다.
  • 설치 패키지는 이전 빌드와 비교해 앱 두 개와 체크섬만 바뀐 것을 확인했습니다.
  • 실차 확인 전 항목: 고가·지하 아이콘과 회전교차로 아이콘의 실제 모양, 거리 필드의 단위 규약, 터널 신호와 공조의 실제 연동.

배운 점은 두 가지입니다. 비슷해 보이는 아이콘을 고르는 것보다, 같은 장치 안의 순정 구현을 기준표로 삼는 편이 훨씬 빠르고 정확했습니다. 그리고 결과를 알려 주지 않는 API에는 “한 번 보내고 끝”이 아니라, 몇 번 다시 보낼지 상한을 둔 재전송을 설계해야 했습니다.
