데이터베이스 정규화

데이터의 중복을 제거하는 정리정돈 과정

관계형 데이터베이스에서 데이터의 중복을 최소화하고 일관성과 무결성을 확보하기 위해 테이블을 논리적으로 분해하는 과정입니다. 이 과정을 통해 데이터 삽입, 수정, 삭제 때 생길 수 있는 이상 현상을 막습니다.

  • 1차 정규형 (1NF): 테이블의 모든 컬럼 값이 더 이상 쪼갤 수 없는 원자값을 갖도록 합니다.
  • 2차 정규형 (2NF): 1차 정규형을 만족하고 부분 함수 종속성을 제거합니다. 복합키의 일부에만 종속되는 컬럼을 별도 테이블로 분리합니다.
  • 3차 정규형 (3NF): 2차 정규형을 만족하고 이행 함수 종속성을 제거합니다. 기본키가 아닌 일반 컬럼에 종속되는 컬럼을 별도 테이블로 분리합니다.

장점: 데이터 중복이 줄어 저장 공간이 절약되고, 무결성이 높아져 데이터 관리가 쉬워집니다.

단점: 테이블이 여러 개로 나뉘면서 조회할 때 Join이 더 많이 필요해져 성능이 떨어질 수 있습니다.

인덱스

데이터베이스의 ‘찾아보기’ 페이지

테이블에서 SELECT 속도를 크게 높이기 위한 자료구조로, 원하는 데이터가 실제로 어디에 저장되어 있는지 위치 정보를 가지고 있습니다.

인덱스는 특정 컬럼의 값과 그 값이 저장된 행의 위치를 키-값 쌍으로 저장합니다. WHERE 절로 데이터를 찾을 때 테이블 전체를 스캔하지 않고 인덱스를 먼저 참조해 데이터 위치로 바로 이동합니다.

장점: 검색과 조회 속도가 매우 빨라집니다.

단점

  • 추가 저장 공간: 인덱스를 만들면 별도의 저장 공간이 필요합니다.
  • 쓰기 성능 저하: INSERT, UPDATE, DELETE 때 인덱스도 함께 갱신해야 해서 쓰기 작업이 느려질 수 있습니다. 그래서 검색이 잦은 컬럼에만 적용하는 것이 좋습니다.

ORM vs Raw SQL

구분 ORM (Object-Relational Mapping) Raw SQL
개념 객체와 데이터베이스를 연결하는 번역기 데이터베이스와 직접 대화하는 언어
정의 객체지향 언어의 객체와 DB 테이블을 자동으로 연결하는 기술 개발자가 SQL 쿼리를 직접 작성해 DB를 조작
장점 생산성: SQL을 몰라도 객체 메서드로 DB를 다룰 수 있어 개발이 빠름
유지보수: SQL 종속성이 낮아 DB를 바꿔도 코드 수정이 적음
가독성: 코드가 직관적이고 비즈니스 로직에 집중 가능		 성능: 가장 최적화된 쿼리를 직접 작성 가능
유연성: 복잡한 쿼리나 특정 DB 전용 기능을 자유롭게 사용
단점 성능: 자동 생성 쿼리가 비효율적일 수 있음
학습 곡선: ORM의 동작 방식을 따로 익혀야 함
제한성: 복잡한 쿼리는 ORM만으로 구현하기 어려움		 생산성: 반복적인 CRUD 쿼리를 모두 직접 작성
유지보수: DB 변경 시 관련 SQL을 전부 수정
보안: SQL 인젝션 같은 공격에 주의 필요
