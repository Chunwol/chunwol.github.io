개요

룸메이트나 가족이 한 그룹 안에서 집안일, 생활비, 공용 물품, 생활 규칙을 관리하고 메신저와 알림으로 소통하는 서비스입니다. 저는 소통팀장으로 참여했고, 공용 물품 목록·등록과 생활 규칙 목록·상세 화면을 담당했습니다.

담당한 흐름

영역 작업 내용
공용 물품 목록·등록 화면, 최종 API 계약 반영, 모바일·반응형 UI
생활 규칙 목록·상세, 동의 상태, 중복 동의와 재진입 시 상태 처리
인증·그룹 진입 로그인 후 그룹 조회·선택, 보호 라우트와 대시보드 진입 흐름
공통 UI 드롭다운, 입력 오류, 모바일 레이아웃과 PC 표 UI 일관성
데이터 갱신 저장 후 캐시 무효화와 목록·상세·메신저 상태 갱신
배포 품질 실제 검사가 수행되는 type-check, 배포 환경변수 로드와 캐시 갱신

공개 저장소에서 본인 작성 프론트엔드 Pull Request 45개가 확인됐습니다. 담당 화면에서 시작해 공통 API 기반, 인증 진입, 상태 갱신, 반응형 UI와 배포 문제까지 팀의 사용자 흐름을 연결하는 작업을 맡았습니다.

구조와 기술 선택

React·TypeScript·Vite를 기반으로 Feature-Sliced Design 경계를 사용했습니다. TanStack Query는 서버 데이터와 갱신을, Zustand는 클라이언트 상태를 맡도록 책임을 나눴습니다. 로그인 성공만 확인하지 않고 사용자가 속한 그룹을 선택한 뒤 올바른 화면으로 들어가는 전체 경로를 보호 라우트와 함께 점검했습니다.

백엔드는 NestJS·Prisma·PostgreSQL로 구성된 팀 서비스입니다. API 계약을 확인하고 일부 로컬 시드 변경에 참여한 근거는 있지만, 백엔드 전체를 개인 담당으로 서술하지 않습니다.

해결한 문제

목록 응답과 상세 응답의 상태 계약이 다르면 화면 안의 임시 상태만 맞고 재진입 후 다시 틀어질 수 있습니다. 생활 규칙 동의와 공용 물품 저장에서 서버 응답, 캐시, 페이지 전환을 하나의 흐름으로 보고 갱신 경로를 정리했습니다.

또한 명령 이름만 존재하던 type-check가 실제 검사를 하지 않는 문제를 수정했습니다. 빌드 명령의 성공 여부뿐 아니라 검사가 유효한지도 확인해야 한다는 경험을 배포 파이프라인에 반영했습니다.
