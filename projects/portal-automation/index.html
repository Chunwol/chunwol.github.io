일정 포털 자동화

자동 입력보다 변경 범위·중복·결과 재조회를 먼저 검증하는 운영형 자동화

월간 일정과 학교 포털의 승인 배정·기존 기록을 연결해 근로 일지 입력을 안전하게 자동화하는 웹앱

화면

개요

학교 포털의 근로 일지를 월간 일정과 연결해 관리하는 웹앱입니다. 근무 일정만 정해 두면 포털 입력까지 이어지도록, 로그인, 학교 계정 연결 확인, 반복 일정과 예외 편집, 승인된 근로 배정 선택, 기존 기록 조회, 자동 입력과 결과 확인을 한 흐름으로 묶었습니다.

사용자 흐름

  1. 웹앱 사용자와 학교 포털 연결 상태를 각각 확인합니다.
  2. 월·요일 반복 규칙과 날짜별 예외, 오전·오후 같은 여러 시간 구간을 편집합니다.
  3. 포털에서 현재 승인된 장학 유형과 근무지를 다시 조회합니다.
  4. 대상 월의 기존 기록을 먼저 읽고 중복될 날짜를 제외합니다.
  5. 승인한 월과 범위에만 입력하고, 등록 후 다시 조회해 실제 결과를 확인합니다.
  6. 수정·삭제도 요청 성공만 보지 않고 변경된 값이나 삭제 후 부재를 확인합니다.

안전한 자동화를 위한 결정

잘못 입력된 근로 기록은 되돌리기 번거롭기 때문에, 얼마나 빨리 입력하느냐보다 틀리지 않게 입력하는 쪽에 무게를 뒀습니다.

  • 일정표에 없는 날짜를 근무일로 추측하지 않고, 잘린 일정과 예외 시간은 사용자가 지정한 원본을 보존합니다.
  • 어떤 날짜에 기존 일지가 하나라도 있으면 그 날짜 전체를 건너뛰어 중복 입력을 막고, 빈 날짜에서는 필요한 여러 시간 구간을 함께 처리합니다.
  • 실제 쓰기 시험과 조회 전용 확인을 월별로 나눴습니다. 특정 달의 임시 기록을 등록·수정·삭제한 뒤 원상 복구하고, 변경하지 않기로 한 달의 기록도 전후가 같은지 확인했습니다.
  • 기능이 있다는 것과 사용자별 예약이 켜져 있다는 것을 따로 관리합니다.

구현과 운영

Node.js와 Express로 사용자·일정·작업 API를 구성하고, Cheerio로 포털 응답을 해석합니다. 세션 갱신, 반복 규칙 이관, 기존 기록 조회 캐시와 작업 이력을 다루며 Docker와 GitHub Actions로 배포 경로를 관리합니다.

운영 페이지와 health 응답, 컨테이너 상태를 확인하고 있고, 컨테이너 자동 시작도 설정했습니다. 다음 운영 점검에서는 NAS를 재부팅한 뒤 서비스가 스스로 복구되는지 시험할 예정입니다.

기술: JavaScript, Node.js, Express, Cheerio, Docker, GitHub Actions
