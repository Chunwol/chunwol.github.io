화면

개요

새 채팅을 열 때마다 이전 프로젝트의 목적, 결정, 실패 원인, 다음 작업을 다시 설명하는 일이 반복돼서 만든 로컬 지식 시스템입니다. 대화 원문을 쌓는 데서 끝내지 않고, 프로젝트별 브리프와 결정 기록, 문제 해결 절차, 작업 세션으로 이어서 필요한 맥락을 빠르게 꺼냅니다.

2026년 9월 기준으로 로컬에 남아 있는 172개 세션과 54,016개 메시지를 모았습니다. 중복을 정리한 31,713개 검토 단위에서도 원래 세션과 메시지 위치를 바로 찾을 수 있게 연결했습니다. 클라우드에만 남아 있는 대화는 내보내기를 받는 대로 추가할 예정입니다.

지식 구조

층 역할
원본 대화, 저장소 조사, 기존 포트폴리오 근거를 그대로 보존
프로젝트 브리프 목적, 구성, 개인 기여, 현재 상태와 다음 확인을 제품 단위로 정리
결정·플레이북 선택 이유와 반복되는 장애의 진단·복구 절차를 재사용 가능한 형태로 분리
세션 날짜별 변경, 검증 결과, 미해결 항목과 다음 행동 기록
전달 필요한 공유 가능 맥락만 새 채팅용 Markdown으로 내보내기

구현

Python 표준 라이브러리와 SQLite로 대화 원문을 가져오고 검색 인덱스를 만들었습니다. 출처가 다른 기록은 세션 ID로 구분하고, 하위 에이전트 로그와 중복된 이관 기록이 성과로 다시 집계되지 않도록 분리합니다.

검색은 정제된 브리프와 해결 절차를 먼저 보여 주고, 더 구체적인 근거가 필요할 때만 원문으로 내려갑니다. 공유용 내보내기는 프로젝트와 관련된 공개 가능 노트만 고르고, 알려진 토큰·개인키 패턴은 가립니다. 백업은 보관함 밖에 ZIP으로 만들고 생성 뒤 무결성을 검사합니다.

정리 원칙

  • 빌드, 배포, 실제 운영 상태를 나눠 기록합니다.
  • 같은 저장소에서 만든 여러 checkout은 하나의 프로젝트로 묶습니다.
  • 팀 전체 기능과 제가 맡은 작업을 구분해 정리합니다.
  • 비밀번호, 토큰, 내부 주소와 원문 대화는 공개 자료에서 자동으로 제외합니다.

지금은 로컬 Markdown과 ZIP 백업으로 쓰고 있고, 여러 기기 동기화는 필요해질 때 연결할 계획입니다.

이 사이트도 같은 구조에서 나왔습니다. 공개로 표시한 프로젝트와 글만 가져와 빌드하도록 해서, 지식 보관과 공개 포트폴리오 사이에 분명한 경계를 뒀습니다.
