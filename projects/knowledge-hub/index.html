개요

새 Codex·Claude 채팅에서도 이전 프로젝트의 목적, 결정, 실패 원인과 다음 작업을 빠르게 가져오기 위해 만든 로컬 지식 시스템입니다. 원문을 단순히 쌓는 데서 끝내지 않고, 프로젝트별 브리프와 결정 기록, 문제 해결 절차, 작업 세션으로 연결합니다.

2026년 9월의 고정된 검토 manifest 기준으로 접근 가능한 172개 세션과 54,016개 메시지를 수집했고, 중복을 제거한 31,713개 검토 단위와 원래 세션 위치의 연결을 보존했습니다. 온라인에만 있고 로컬에 남지 않은 대화까지 수집했다고 주장하지 않습니다.

지식 구조

층 역할
원본 Codex·Claude 대화, GitHub·로컬 저장소 조사, 기존 포트폴리오 근거 보존
프로젝트 브리프 목적, 구성, 개인 기여, 현재 상태와 다음 확인을 제품 단위로 정리

세션 날짜별 변경, 검증 결과, 미해결 항목과 다음 행동 기록
전달 필요한 공유 가능 맥락만 새 채팅용 Markdown으로 내보내기

구현

Python 표준 라이브러리와 SQLite로 대화 원문을 가져오고 검색 인덱스를 구성했습니다. Codex, Claude Code, Claude Desktop/Cowork처럼 출처가 다른 기록을 세션 ID로 구분하고, 하위 에이전트 로그와 중복된 이관 기록이 성과로 다시 집계되지 않도록 분리합니다.

프로젝트 검색은 정제된 브리프와 해결 절차를 먼저 보여 주고, 더 구체적인 근거가 필요할 때만 원문으로 내려갑니다. 공유용 내보내기는 프로젝트와 관련된 공개 가능 노트만 선택하며, 알려진 토큰·개인키 패턴을 마스킹합니다. 백업 도구는 보관함 밖에 ZIP을 만들고 생성 후 무결성을 검사하도록 구성했습니다.

운영 원칙

  • 완료, 진행, 실패, 미확인을 구분하고 빌드 성공을 실제 배포 성공으로 바꾸어 쓰지 않습니다.
  • 같은 원격 저장소의 여러 checkout을 중복 프로젝트로 세지 않습니다.
  • 팀 저장소의 기능과 개인 기여를 분리하고, 공개 GitHub·문서·실행 결과를 근거로 연결합니다.
  • 비밀번호, 토큰, 내부 주소와 원문 대화는 포트폴리오 콘텐츠로 내보내지 않습니다.
  • 여러 기기 동기화는 현재 범위에서 제외하고 로컬 Markdown과 검증 가능한 백업을 우선합니다.

이 사이트 자체도 이 구조에서 공개 대상으로 선택한 프로젝트와 글을 가져와 빌드할 수 있도록 설계했습니다. 지식 보관과 공개 포트폴리오 사이에 명시적인 공개 범위를 두는 것이 핵심입니다.
