화면

개요

학교 실습실의 강의실 17곳, PC 696대를 관리하려고 만든 통합 관제 시스템입니다. 실습 지원실에서 근로하며 수업 전에 PC를 켜고, 프로그램을 설치하고, 수업이 끝나면 끄는 일을 반복하다가 이 과정을 한 화면으로 모았습니다. 지금도 실제 강의실 운영에 사용하고 있습니다.

구성

  • 서버: Spring Boot. 에이전트의 상태를 모으고 명령을 전달합니다.
  • 에이전트: 강의실의 Windows PC마다 설치되어 서버의 명령을 실행하고 결과를 돌려보냅니다.
  • 대시보드: React와 TypeScript로 만든 관리 화면입니다.
  • 운영: NAS의 Docker에서 돌아가며, GitHub의 self-hosted runner로 새 버전을 배포합니다.

기능

  • 강의실별 좌석 배치도로 PC 상태 확인
  • Wake-on-LAN 켜기, 재시작, 종료를 강의실이나 검색 결과 단위로 일괄 실행
  • 버전을 고정한 PowerShell 스크립트 실행 (Windows Update 차단과 해제 등)
  • PC 사이 직접 파일 전송과 에이전트 패키지 배포
  • 네트워크 사용량, 강의실 가동률, 기간별 보고서와 PDF 출력
  • 브라우저에서 바로 여는 noVNC 원격 화면

운영하면서 신경 쓴 점

명령은 보내는 것보다 결과를 확인하는 게 중요했습니다. 명령마다 대기, 진행, 완료, 실패 상태를 나눠 기록하고, 지금까지 8만 9천 건이 넘는 명령 이력을 쌓았습니다. 스크립트는 실행할 때의 버전과 SHA-256, 대상별 작업 ID를 함께 남겨 어떤 PC에 무엇이 실행됐는지 나중에도 추적할 수 있게 했습니다.

파일을 배포할 때도 받는 PC에서 SHA-256을 검증한 뒤 반영하고, 임시 전송 서버와 방화벽 규칙은 작업이 끝나면 자동으로 정리합니다.

대량 배포 설계

30GB짜리 파일을 800대에 보내면 전송량만 24TB입니다. 서버가 한꺼번에 밀어 넣으면 서버 한 곳이 병목이 되고 실패도 한꺼번에 번지기 때문에, 설계 단계에서 아래 원칙을 정했습니다.

원칙 내용
단계적 확산 1~3% 카나리 배포 후 10%, 30%, 나머지 순으로 넓히고, 실패율이 기준을 넘으면 자동으로 멈춤
이어받기 32MB 조각 단위로 받고 완료한 조각을 기록해, 끊겨도 남은 조각만 다시 요청
무결성 우선 조각마다 해시를 확인하고 전체 파일 SHA-256이 맞아야 임시 파일을 원래 이름으로 교체
경로 제한 허용한 폴더에만 쓰고 상위 경로와 시스템 경로는 차단
감사 기록 누가 언제 무엇을 어디로 배포했는지 남김

설계서에는 서버가 직접 보내는 대신 강의실 단위 중계 노드와 PC 간 분산으로 나눠 보내는 구조까지 정리했습니다. 지금 운영에서 쓰는 기능은 PC 사이 직접 전송과 에이전트 패키지 배포입니다.
